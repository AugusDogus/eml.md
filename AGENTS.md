- Follow-up TanStack Intent commands run from the project: `npx @tanstack/intent@latest install`, `npx @tanstack/intent@latest list`, `bunx @tanstack/intent@latest load @tanstack/router-plugin#router-plugin`, `bunx @tanstack/intent@latest load @trpc/server#server-setup`.

## Stack And Integrations

- React 19 with Vite.
- TanStack Router in router-only SPA mode with file-based routes under `src/routes`.
- TanStack Router plugin must stay before `viteReact()` in `vite.config.ts`; the loaded Router plugin skill calls this out as critical.
- Tailwind CSS v4 via `@tailwindcss/vite` and `src/styles.css`.
- `postal-mime` parses `.eml` files directly in the browser for the core conversion flow.
- TanStack Query is wired through a shared `QueryClientProvider` in `src/main.tsx`.
- tRPC packages are installed, but the app has no tRPC transport or backend. `src/lib/trpc.ts` keeps a type-only placeholder for future offline/local typing.
- Bun is the package manager; use `bun install`, `bun --bun run dev`, `bun --bun run build`, and `bun --bun run test`.

## Environment Variables

- No environment variables are required for the current app.
- Do not add required API URL, database, auth, or server secrets unless the app's offline-only requirement changes.

## Deployment Notes

- This is a portable frontend SPA with no backend, API routes, server functions, database, or external network dependency.
- `.eml` parsing and Markdown generation must happen on device only; do not upload email contents or add remote parsing services.
- Production output comes from `bun --bun run build` and can be hosted by any static file host.
- Configure the static host to serve `index.html` as the fallback for client-side routes.

## Architectural Decisions

- Preserve router-only mode instead of TanStack Start server features because the original brief asks for a completely offline frontend SPA.
- Keep integrations minimal: Query provider is available for local/client state and cache workflows; tRPC remains represented without introducing HTTP calls.
- Prefer local data, browser storage, or bundled static assets over runtime backend calls.
- The core app flow is drag/drop or click-to-upload `.eml`, convert the readable conversation body into Markdown, then copy or download the `.md` output.
- Email headers are not a primary output. Use parsed sender/recipient metadata only when it helps label the conversation for agent-readable context.
- Keep generated Router files generated by the TanStack Router plugin; do not hand-edit `src/routeTree.gen.ts`.

## Known Gotchas

- The exact scaffold command included `--add-ons tanstack-query,tRPC`, but the TanStack CLI ignored add-ons because `--router-only` was set.
- The generated README referenced TanStack Start server/API examples; keep docs aligned with SPA-only behavior.
- Intent skill loading may fail transiently with Bun/npm extraction errors. Re-run `bunx @tanstack/intent@latest list` and load the most specific local skill before library-specific changes.
- tRPC server adapters should not be added unless the no-backend requirement changes.
- Quoted reply splitting is heuristic because email clients format threads differently. Preserve readable conversation order over exhaustive RFC header rendering.
